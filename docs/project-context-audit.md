# 项目与 AI 上下文隔离核查（2026-11-21）

本次检查针对“窗口中的项目、编辑文件、AI 工具目录和后台结果必须属于同一个项目”。
之前只验证打开另一个项目后新窗口是否正确，漏掉了另存为、关闭、重命名及延迟结果，
不能据此断言整条流程已经检查完整。

## 核查与修复

| 范围 | 当前行为与验证 |
|---|---|
| 普通启动 | 显示欢迎页，由用户选择项目；旧工作区、最近记录不会自动打开。显式启动路径仍有效。 |
| Open / Open Folder / Open Recent | 共用项目归属判断；Recent 先解析所属主文件。其他项目进入独立进程窗口，原标签和未保存修改保留。 |
| 子文件、共享文件、符号链接 | 子文件先打开也使用所属根目录；已被项目包含的文件留在原窗口；指向其他项目的符号链接按真实路径另开窗口。 |
| 同目录多个主文件 | 独立主文件使用独立窗口及历史；选中共享章节不会偷偷改变当前窗口的编译主文件。 |
| New / New from Template | 已打开项目时使用新窗口，新窗口不继承旧项目的标签、对话或工具目录。 |
| Save As | 跨项目目标先写入成功，再把该标签转交独立窗口。原项目其他标签保留；旧保存确认框不会因标签索引复用而关闭另一文件。 |
| 关闭最后标签 | 当场清空项目、AI 草稿/消息/附件、文件树、PDF、诊断和日志；下一个命令不需要等 UI 下一帧才拿到正确上下文。 |
| 重命名目录或文件 | 同步更新标签路径、项目目录、根文件、导航和最近记录；相关后台任务停止，文件树与索引重建。 |
| AI 当前文件 | 每次提问重新捕获当前相对路径、根文件、修改状态、光标和选区。开启正文时发送当前未保存缓冲区；关闭正文时仍告知文件身份。 |
| 同名文件 | `sections/notes.tex` 与 `appendix/notes.tex` 分别显示和发送，不能只靠 `notes.tex` 判断。 |
| 延迟 AI 工具调用 | 请求捕获发起时的目录；直接改变目录时先取消旧轮次。另开 B 窗口时，仍在运行的 A 请求继续只访问 A。 |
| 回答插入、右键 AI、行内补全 | 保存来源项目、根文件和文件身份；插入必须匹配来源文件。标签索引/版本号相同也不能把旧补全用于另一文件。 |
| 回答中的文件链接 | 按来源项目检查后再解析，并检查真实路径仍在当前目录内；旧项目链接不会用新项目同名文件顶替。 |
| AI 历史 | 按所属根文件隔离；旧目录级历史只有归属唯一时才显示，歧义数据保留。重命名时迁移归属与来源路径，支持连续重命名。目标名称的旧缓存独立保留，不混入当前历史。 |
| 无来源的旧回答 | 可以阅读和复制，禁止自动插入当前文件，避免猜测原始目标。 |
| 未保存文稿 | AI 身份显示 Untitled，工具和 Git 不会把编译临时目录当成用户项目。 |
| Git | 换目录时丢弃旧快照、差异、待执行队列和 AI 提交说明任务；已启动的 Git 子进程仍只作用于其发起目录。 |
| 编译与 PDF | 旧任务完成时仍可发布自己的 PDF，但不能覆盖新项目的 PDF、错误列表、日志和状态。退出前强制编译及失败阻止退出的既有测试继续通过。 |

## 验证证据

- `cargo test --workspace`：414 项通过，0 失败；1 个字号测量工具按原配置忽略。
- `cargo fmt --all`；engine、UI、i18n、桌面 app 的 all-target Clippy，`-D warnings` 通过。
- 永久回归位于 `crates/engine/src/project_context_tests.rs`、`opening.rs`、`ai.rs`、
  `inline.rs`，以及 `crates/ui/tests/lifecycle.rs`、`crates/ui/src/ai_panel.rs` 和桌面启动测试。
- 关闭最后标签、跨项目另存为、项目目录重命名的回归先失败后修复；旧编译诊断测试同样先失败后修复。
- 真实本机 TeX 测试：A 编译尚未被处理时关闭 A、打开 B；A 完成并发布 A 的 PDF，B 保持自己的根文件且无 A 的日志、错误或预览。
- 原生双项目联调：A 有未保存修改，暂停 A 的 AI 请求；通过 Recent 打开 B 独立窗口。
  B 执行真实工具轮次，只列 B 文件；放行 A，只列 A 文件。检查了请求体，B 不包含 A 的对话。
  再从 A 新建模板，第三个窗口没有项目或继承的对话；正常关闭 A，B 仍可操作。
- 使用本地模拟 AI HTTP 服务，没有向外部模型发送测试项目。检查了英文、简体中文、浅色及深色截图，
  也核对了两个同名标签切换和关闭正文后的当前文件提示。

## 交付与覆盖边界

修复在当前源码和开发构建中。核查时 `/Applications/TexCraft.app` 的版本仍为 **0.5.0**，
没有替换安装包、提交代码或发布版本。控制接口新增 `ui.executable` 与 `ui.processId`，
用来核对当前检查的具体构建，避免把开发版通过误认为安装版已更新。

本次实际运行环境为 macOS、本机 TeX 和本地模拟 AI 服务。未在 Windows/Linux 或真实远程模型上复测。
根文件的判断仍依赖已有主文件、magic comment 与包含关系规则；无归属信息的任意文本无法凭空识别用户心目中的项目边界。
