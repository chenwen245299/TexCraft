# TexCraft devlog

## texcraft-synctex

- Pure-Rust SyncTeX reader (`crates/synctex`): gzip auto-detect, preamble/content/postamble/post
  scriptum, all record kinds (`[ ] ( ) v h k g r $ x f < > ! c`, `,=` compressed v, columns),
  magnification/unit/offsets; forms are expanded at their `f` references. Reproduces the
  reference tool's book-keeping (visible hbox extents, box boundaries, mean lines, friend-list
  quirks) so answers match `synctex view`/`edit`.
- API kept; added `forward_with_hint` (CLI order, page hint honoured) and `inverse_candidates`
  (up to 2, like `synctex edit`). `forward` dedups rects; file matching: exact, canonical,
  relative to the synctex dir, then longest trailing path / file name (case-folded last).
- Oracle (TeX Live 2022 `synctex` 1.21; pdflatex, xelatex, lualatex, plain pdftex `\mag`,
  `\pdfxform`; 7 fixtures in `tests/data`, `generate.py` regenerates): forward 418/418 queries
  identical (±0.5 pt), inverse 10190/10190 points same file+line+column.
- Robustness: random bytes, truncations (plain and gzip), line mutations, grammar fuzz, 100k
  nesting, i32-overflow numbers: no panics. Truncated files stay searchable up to the damage.
  Perf: 2.2 MB uncompressed parses in ~9 ms (release).
- 26 tests. Open: the CLI ignores page hints and has no form definitions in TL2022 output, so
  hint ordering and `<form>` expansion are only covered by synthetic tests; LuaTeX second
  candidates with tagless kerns are dropped (CLI shows them).

## texcraft-log

- TeX `.log` parser (`crates/log`, no deps): line-oriented; known messages are parsed as
  blocks (message + wrapped/continuation lines + `l.<n>` context + help) and never
  paren-scanned; all other lines feed TeX's `(file ... )` stack. File names wrapped at the
  79-column (LuaTeX: 80) `max_print_line` limit are re-joined, preferring cuts that end in a
  known extension; names with spaces, quoted names and Tectonic's extension-less `\input`
  names are recognised; unwrapped logs (large `max_print_line`) are detected.
- Covers `! ` and `-file-line-error` errors (incl. wrapped long paths), Emergency stop /
  fatal markers, runaway arguments, Lua errors, LaTeX/package/class/font warnings with
  continuations, undefined refs/cites, rerun requests (labels, rerunfilecheck, natbib,
  biblatex), bad boxes (paragraph/alignment/detected/`\output`), `pdfTeX warning` (also
  mid-line), `Missing character`, `Output written on` / `No pages of output`. `.blg`: BibTeX
  errors (`---line N of file F`, `---while reading file`), `Warning--` (+`--line` locations),
  biber `WARN`/`ERROR` with temp `.bib` copies mapped back. API unchanged (docs added).
- Oracle: 13 real fixtures in `tests/data` (latexmk pdf/xelatex/lualatex, plain pdflatex,
  missing package, missing `\begin`/`\end{document}`, fontspec, biblatex, bibtex, tectonic
  continue/halt), regenerated by `generate.sh` (home dir scrubbed, same length); every issue
  asserted (severity, file, line, message, log line). 47 tests incl. truncation/garbage/
  pathological fuzz. Perf: 50k-line log in ~10 ms (release).
- Open: biber `.blg` only covered synthetically (MacTeX 2022 biber is x86_64-only here);
  Tectonic extension-less names without a directory are heuristic (bare word after `(`);
  TeX attributes a paragraph's bad box to the file open when it ends.

## Completion no longer doubles braces (2026-10-15)

- Completing `\beg` leaves `\begin{|}`; completing the environment then inserted `equation}` and
  the `\end`, pushing the old `}` behind it (`\end{equation}}`). Accepting a completion is now a
  pure, tested function (`syntax::completion::completion_edit`): an existing `}` after the word is
  reused, and a command whose arguments are already typed (`\textb|{x}`) completes the name only.
  Checked in the app over the control channel (`\beg` Tab `equ` Tab, `\end{equ` Tab, `\textb` Tab).
- Windows: compiles in principle (paths, `taskkill`, copies instead of symlinks are handled) but is
  untested; no native menu bar, OS title bar above the toolbar, Segoe UI instead of SF, no glass,
  spell checking limited to the built-in word list.

## Faster XeLaTeX/LuaLaTeX live passes, inline AI suggestions (2026-10-16)

- Live passes per engine (demo article with amsmath/hyperref, release CLI, warm caches):
  pdfLaTeX 0.07 s (unchanged), XeLaTeX 1.15 → 0.35 s (with TexCraft's CJK setup 1.2 → 0.35 s),
  LuaLaTeX 0.80 → 0.45 s. Where XeLaTeX's time went: start-up 0.17 s, xeCJK 0.2 s, the rest of
  the preamble 0.15 s, xdvipdfmx 0.25 s (0.15 s of it reading the full font maps).
- XeLaTeX and LuaLaTeX precompiled preambles (`live::format_source`): the dump reads the preamble
  with OT1 (TFM) fonts so no system font is loaded, xeCJK is loaded after the class with
  `\selectfont` paused, `\endofdump` sits on the `\begin{document}` line, and each pass restores
  TU (or keeps the preamble's T1) and sets the CJK fonts. Both edits stay on existing lines.
  XeTeX writes a broken format after "Can't \dump a format with native fonts": treated as a
  failure. LuaLaTeX dumps check for package callbacks (beyond the kernel's `ltx.*`, luaotfload,
  `tracingstacklevels`) and Lua-loaded fonts. Formats are stored uncompressed (XeTeX 0.24 →
  0.16 s, LuaTeX 0.62 → 0.55 s).
- xdvipdfmx: a local `dvipdfmx.cfg` (found first through `DVIPDFMXINPUTS=.:`) names a map of the
  families the pass's TFMs belong to (`-recorder`); 0.25 → 0.09 s. LuaTeX reads a reduced
  `pdftex.map` in its folder like pdfTeX (0.05 s). Reduced-map passes hide PK fonts
  (`PKFONTS`/`TEXPKS`), so a missing family fails visibly instead of turning into a cached
  bitmap font; xdvipdfmx's "Font file name … was assumed" names the family to add.
- Inline AI suggestions (`engine/src/inline.rs`, `ai/src/inline.rs`, `ui/src/ai_inline.rs`):
  after a pause (default 0.5 s) the text around the caret (4,000 / 1,000 characters) goes to the
  chosen model (the Assistant's by default) with a small token budget (48 a line, `max_tokens`,
  `max_completion_tokens` on OpenAI); the answer is cleaned (fences, a repeated line start, what
